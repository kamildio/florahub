# Ручная сверка Kaspi и управление доступом

6 ноября 2026. Владелец выбрал личные уведомления Telegram и начало оплаченного месяца после текущего доступа. Получатель — владелец в личном Telegram; Bot API token ещё не настроен. Используется @MaXiFlora_Oficial_bot. Числовой chat ID хранится только в приватной конфигурации сервера.

Клиент: Тарифы → создать заявку с фиксированной серверной ценой → открыть https://pay.kaspi.kz/pay/03wnshty → перевести деньги → «Я оплатил». Заявка попадает в review. Ни ссылка, ни возврат из Kaspi, ни кнопка клиента не подтверждают деньги.

Владелец: Администрирование → Оплаты и доступ. После свежего MFA сверяет реальную банковскую операцию, вводит уникальный номер, фактическую сумму и основание решения. Подтверждение атомарно создаёт один календарный месяц. Активный доступ и уже выданные будущие периоды не сокращаются. Периоды активируются штатным таймером/каждой мутацией, лимит и цена фиксируются на момент заявки. Повтор запроса не начисляет месяц повторно. Номер операции нормализуется и не может использоваться для другой оплаты.

Ручная выдача: выбрать клиента, тариф, 1–12 месяцев и основание. Период также добавляется после текущих. Отзыв: версия доступа + причина; отменяет активные и будущие периоды, сохраняет заявки и заказы, сам по себе не возвращает деньги. Действие и автор записываются в журнал. Уведомление клиента в кабинете.

Бот: durable outbox, lease 60 секунд, повторные попытки планировщиком с backoff до часа. Сообщение содержит только номер заявки, тариф, сумму и ссылку на админку; контакты, документы и реквизиты клиента не отправляются. Telegram не предоставляет exactly-once: при неоднозначном сетевом сбое повтор уведомления возможен, финансовое начисление при этом остаётся однократным.

Перед открытием приёма платежей: владелец сохраняет Bot API token и свой числовой ID в .payments-private.env вне public, проверяет получение уведомления и утверждает опубликованные условия оплаты/возврата. MANUAL_PAYMENTS_ENABLED=false по умолчанию; платежи закрыты, пока все три поля не настроены. Не включать приём только по наличию имени бота. Не отправлять токен в чат и не добавлять приватный файл в Git.

Проверки: unit — снимок тарифа/идемпотентность/чужая заявка/совпадение суммы/уникальная банковская операция/очередь после действующего периода/отзыв/устаревшая версия/MFA/outbox; HTTP — реальный обработчик, auth/origin/MFA, приватная проекция, подтверждение и повтор, отзыв. Все данные синтетические, Telegram-запрос в API-тесте подменён.
